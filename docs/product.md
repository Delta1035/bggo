# 产品范围与当前状态

## 产品目标

BGGo 面向希望用同一套工具管理桌面和编辑器视觉背景的用户。近期目标是先把 Linux 桌面与 VS Code 的本地壁纸体验做稳定，再完善 Windows、分发和更新能力。

项目遵循以下原则：

- 桌面应用使用 MyGo 原生 UI，不引入 Web 前端运行时。
- 默认处理本地图片，不上传用户图片。
- 系统权限必须最小化、可解释、可恢复。
- 生产更新只分发可校验的软件包，不远程执行任意脚本或代码。
- Linux 优先，但架构和发布流程不能阻碍 Windows 支持。

## 当前能力

### 桌面应用

- 选择和预览 JPG、JPEG、PNG、WebP、BMP。
- 使用覆盖、适应、拉伸三种方式预览图片。
- 保存最多 20 条最近使用记录。
- 在 GNOME/Ubuntu、KDE Plasma、XFCE、Cinnamon、MATE 上调用对应系统接口设置壁纸。
- 在 Windows 上通过 `SystemParametersInfoW` 设置系统壁纸。

### VS Code 扩展

- 选择本地 JPG、JPEG、PNG、WebP、BMP、GIF 作为工作台壁纸。
- 配置透明度、模糊半径和对齐位置。
- 重新生成或关闭 BGGo 管理的壁纸。
- Linux 上检测工作台写权限，并使用 `pkexec` 和 `setfacl` 请求一次最小授权。
- 兼容 VS Code 沙箱所需的 `vscode-file://vscode-app/...` 本地资源地址。

## 明确不在当前版本内

- 在线账号、云同步和图片上传。
- 在线壁纸商店或第三方图库抓取。
- 定时轮换、收藏、标签、多显示器独立设置。
- 系统托盘、开机启动、国际化。
- 稳定版自动更新、签名安装包和崩溃上报。
- VS Code Marketplace / Open VSX 正式发布。

这些能力不是被否决，而是进入 [路线图](roadmap.md) 后再按优先级实现。

## 已知限制

- Linux 桌面支持来自命令适配，尚未完成各发行版和桌面版本的真机兼容矩阵。
- Windows 已有实现和构建产物，但仍需要 Windows 10/11 真机验证。
- 桌面预览会同步读取和解码整张图片，超大图片可能短暂阻塞 UI。
- 最近使用记录直接保存本地绝对路径；图片移动或删除后记录会在下次启动时过滤。
- VS Code 方案依赖 `be5invis.vscode-custom-css`，该扩展会修改 VS Code 工作台文件，因此 VS Code 可能显示“安装似乎损坏”。
- VS Code 更新可能替换工作台文件，之后需要重新启用样式或修复权限。
- 当前没有自动恢复、诊断包或一键卸载清理流程。

## Alpha 退出条件

进入 Beta 前至少需要满足：

- Linux 和 Windows 兼容矩阵中的必测环境通过核心流程。
- 配置写入具备原子性，超大图片不会明显阻塞 UI。
- VS Code 的启用、关闭、升级后恢复和冲突扩展场景有明确测试结论。
- CI 覆盖 Go 检查、扩展检查和目标平台构建。
- 版本、变更日志、构建产物、校验和与发布步骤可复现。
- 用户能够从文档完成安装、使用、恢复和卸载。
