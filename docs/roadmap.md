# 路线图与 Agent 任务卡

当前目标是把“可运行 Alpha”推进到“可公开测试 Beta”。任务按优先级排列，每张任务卡都可以交给独立 Agent 在独立分支或 worktree 中完成。

## 执行规则

给所有 Agent 附带以下约束：

```text
请在独立分支或独立 worktree 中完成任务。
先阅读 docs/ 中与任务相关的文档，并核对当前代码，不要只按任务描述猜测实现。
保留共享工作区已有的未提交改动，不修改或提交任务范围外的文件。
提交前运行任务要求的检查，汇报变更摘要、风险和测试结果。
commit 前必须让项目负责人确认。
涉及网站或任何新的前端技术栈时，必须先询问项目负责人。
```

## 依赖关系

```text
BG-001 版本规范 ─→ BG-006 CI ─→ BG-008 自动发布 ─┬→ BG-009 桌面更新
                                                    ├→ BG-012 官网下载
                                                    └→ BG-013 扩展商店

BG-002 核心重构 ───────────────────────────────────→ BG-014 桌面/扩展联动
BG-007 恢复诊断 ───────────────────────────────────→ BG-011 用户文档完善
BG-003/BG-004/BG-005 ──────────────────────────────→ Beta 发布门槛
```

不同文件范围且没有依赖的任务可以并行。涉及版本、流水线和发布的任务应依次合并，避免多个 Agent 同时修改相同配置。

## P0：公开测试前

### BG-001 统一版本和变更记录

**目标**：让桌面应用和扩展的版本、Tag、变更日志有唯一规则。

**范围**：确定独立版本或统一版本；新增 `CHANGELOG.md`；记录 Tag 命名、预发布规则和版本修改位置；检查构建产物版本来源。

**验收**：文档中只有一套无歧义规则；能从 Tag 和产物名称判断组件及版本；至少演练一次不发布的版本变更；不提交生成的安装包或 `.vsix`。

**依赖**：无。后续 `BG-006`、`BG-008` 依赖本任务。

### BG-002 桌面核心解耦和可靠存储

**目标**：避免大图阻塞 UI，并确保最近记录不会因中断而损坏。

**范围**：抽离可测试的应用服务；异步读取/解码图片；设置合理的文件大小和像素保护；配置采用同目录临时文件和原子替换；定义损坏配置恢复方式；系统壁纸适配器可注入。

**验收**：超大或损坏图片不会冻结或崩溃；写入中断不破坏上一份配置；竞态检查通过；新失败路径有测试和用户提示；`go test -race ./...`、`go vet ./...`、`go tool mygo vet` 通过。

**依赖**：无。建议在 `BG-014` 前完成。

### BG-003 Linux 真机兼容矩阵

**目标**：验证并修复主流 Linux 桌面设置壁纸的真实行为。

**范围**：至少覆盖 Ubuntu GNOME、原生 GNOME、KDE Plasma、XFCE、Cinnamon、MATE；记录 X11/Wayland、发行版版本、缺少命令、暗色模式和多显示器行为。

**验收**：每个目标环境有可复现记录；支持项通过选择、应用、重启会话检查；不支持项有清晰错误和文档；修复包含相应单元测试或命令模拟测试。

**依赖**：可以与 `BG-002` 并行，若两者同时改系统适配器需协调合并顺序。

### BG-004 Windows 10/11 真机验证

**目标**：确认 Windows 安装、中文路径和壁纸行为可用。

**范围**：Windows 10、Windows 11；amd64；安装、启动、选择多种格式、含中文/空格路径、重启保持、卸载；评估填充方式和多显示器限制。

**验收**：两代系统有测试记录；核心流程通过；安装程序无意外告警或明确记录未签名告警；失败能给出可操作提示；确认是否需要 Windows 专用图片转换或样式设置。

**依赖**：无。

### BG-005 VS Code 安全、恢复和兼容性

**目标**：把当前可用的注入方案变成可测试、可恢复的 Beta 能力。

**范围**：为工作台定位、路径边界、URI 迁移、导入合并、权限错误补测试；验证官方 deb/rpm、snap、Flatpak 以及常见 Code 分支；测试冲突扩展、升级恢复、关闭和卸载；设计 ACL 撤销策略。

**验收**：支持矩阵明确；官方支持安装方式的选择、配置、关闭、升级后恢复通过；不覆盖其他扩展的 imports；权限目标始终限制在应用目录；用户能按文档恢复官方工作台。

**依赖**：无。

### BG-006 CI 质量门禁

**目标**：每次变更自动验证代码质量和构建能力。

**范围**：Go 测试/race/vet/MyGo vet；扩展 pnpm 冻结安装、类型检查和生产依赖审计；Linux/Windows 构建检查；依赖缓存；构建产物保留策略。

**验收**：Pull Request 自动运行；失败阻止合并；pnpm 版本固定；流水线没有提交或泄露构建产物和 Secret；README 显示或链接状态。

**依赖**：`BG-001`。

### BG-007 恢复、卸载和诊断

**目标**：让用户在失败时可以自助恢复，并生成不泄露隐私的诊断信息。

**范围**：清空最近记录；桌面应用配置损坏恢复；VS Code 关闭与残留清理；权限说明；日志级别和脱敏规则；诊断信息模板。

**验收**：桌面和扩展各有已验证的恢复路径；卸载后不会影响原图；诊断输出默认隐藏用户名、主目录和图片文件名；用户指南同步更新。

**依赖**：无。`BG-011` 依赖本任务的最终行为。

## P1：Beta 发布能力

### BG-008 自动构建、签名和 Release

**目标**：从受保护 Tag 可复现地产生 Beta 发布。

**范围**：Linux/Windows 构建矩阵；产物命名；SHA-256；草稿 Release；签名方案；预发布批准；构建来源记录。

**验收**：在干净 Tag 上生成文档约定的全部产物；校验和正确；Secret 只对受保护发布任务可用；安装和启动冒烟测试通过；支持撤回预发布。

**依赖**：`BG-001`、`BG-006`。

### BG-009 MyGo 桌面自动更新

**目标**：提供可校验、可回滚的桌面更新，而不是运行任意远程代码。

**范围**：稳定/Beta 通道；签名更新清单；平台与架构匹配；下载、哈希和签名校验；用户确认；失败回滚；关闭检查更新选项。

**验收**：篡改清单和篡改安装包均被拒绝；断网与下载中断不影响当前版本；升级和回滚有真机记录；远程清单不能执行代码。

**依赖**：`BG-008`。

### BG-010 在线壁纸目录和内容更新

**目标**：不发布新应用也能更新经过签名的壁纸元数据和静态资源。

**范围**：JSON Schema；清单签名；版权和来源字段；缓存、限额、取消、重试、离线降级和下架策略；内容安全审核。

**验收**：离线可使用最后一次有效缓存；签名或哈希错误不会展示内容；每张图能追溯许可证和作者；清单不支持代码字段；缓存可清理。

**依赖**：建议复用 `BG-009` 的签名与通道基础设施。

### BG-011 用户和开发文档完善

**目标**：让新用户和贡献者无需阅读源码即可完成常见流程。

**范围**：安装/升级/卸载；平台截图；兼容矩阵；隐私和权限；贡献指南；Issue 模板；发布故障处理；文档版本标识。

**验收**：由未参与开发的人按文档完成一次 Linux 安装与 VS Code 恢复；命令在干净环境验证；截图不包含隐私；文档与当前 Beta 行为一致。

**依赖**：`BG-007`，并等待核心行为稳定。

### BG-012 官网和下载站

**目标**：提供可信的产品介绍、文档入口和平台下载。

**范围**：首页、功能、下载、版本/校验和、安装说明、FAQ、隐私、许可证和源码链接；无障碍、移动端、SEO 和基础分析策略。

**前置决策**：这是前端任务。Agent 开始创建项目前必须询问项目负责人，确认 Astro、VitePress、Next.js 或其他技术栈、部署平台、域名和视觉方向。当前仓库不得预先创建网站脚手架。

**验收**：下载链接只指向已签名 Release；版本与校验和自动同步；移动端和桌面可用；无秘密信息；分析默认尊重隐私；Lighthouse 和无障碍达到双方约定门槛。

**依赖**：`BG-008`。技术选型需人工确认。

### BG-013 VS Code Marketplace / Open VSX 发布

**目标**：让用户通过扩展商店安装和更新扩展。

**范围**：Publisher 所有权；商店图标、说明、隐私和权限披露；依赖扩展；版本自动发布；Marketplace/Open VSX 差异；回滚和弃用策略。

**验收**：两个商店页面信息一致；安装后依赖正确解析；发布令牌受保护；从旧版升级保留配置；离线 `.vsix` 仍可下载。

**依赖**：`BG-001`、`BG-005`、`BG-006`、`BG-008`。

### BG-014 桌面端与 VS Code 联动

**目标**：允许用户从桌面应用选择是否同步壁纸到 VS Code。

**范围**：定义稳定的本地协议或配置边界；检测扩展是否安装；显式授权同步；并发修改；版本兼容；失败时各自独立可用。

**验收**：默认不修改 VS Code；用户明确启用后才同步；桌面和扩展任一未运行时不丢配置；协议有版本；路径和内容经过校验；关闭联动可恢复独立状态。

**依赖**：`BG-002`、`BG-005`。

## P2：体验和长期维护

### BG-015 高级壁纸能力

收藏、标签、定时轮换、多显示器、系统托盘和开机启动。先分别形成需求和平台限制，不应一次性塞进一个大改动。

### BG-016 国际化与无障碍

抽离用户可见文本；至少规划简体中文和英语；键盘导航、焦点顺序、对比度、屏幕阅读器标签和减少动画设置纳入验收。

### BG-017 日志、崩溃报告和诊断包

定义本地日志轮换、脱敏、用户主动导出和崩溃处理。任何远程遥测或上传都必须另行获得产品决策，并提供明确同意和关闭方式。

## 推荐分派顺序

第一批可并行：`BG-001`、`BG-002`、`BG-003`、`BG-004`、`BG-005`、`BG-007`。

第二批：合并 `BG-001` 后做 `BG-006`；兼容性和恢复结论稳定后做 `BG-011`。

第三批：`BG-006` 完成后做 `BG-008`，再并行启动 `BG-009`、`BG-012`、`BG-013`。`BG-010` 和 `BG-014` 应在基础协议稳定后安排。
